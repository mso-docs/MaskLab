03 / GETTING STARTED & HELP

Try MaskLab, step by step.

For judges: explore saved evidence in this page, or download the full local app to try the complete research workflow.

  1. Check the prerequisites. Install Python 3.14. The test build needs internet for its first dependency installation; it needs no Node, GPU, Docker or API key.
  2. Download and extract the ZIP. Open a terminal in the extracted masklab-test-build folder, alongside run.py and requirements.lock.
  3. Run your platform’s commands below. Keep the terminal open, then visit http://127.0.0.1:8000 in your browser.

The ZIP includes the compiled app, a hash-locked dependency list and the saved real study.

Linux / macOS

Open a terminal in the extracted masklab-test-build folder.

python3.14 --version
python3.14 -m venv .venv

Windows PowerShell

Install Python 3.14, then open the extracted folder.

py -3.14 --version
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps masklab-0.1.0.dev0-py3-none-any.whl
.\.venv\Scripts\python.exe run.py

Your first five minutes

  1. Inspect real results. In Studies → Portable evidence, click Inspect archive saved-pu… (the bundled saved-public-replication archive). It opens 4,050 saved real Nemotron responses without making model calls.
  2. Follow a result to its evidence. Select a condition bar or denominator, then use Response explorer to compare a question across roles and belief frames. Filter INVALID to see the retained failures.
  3. Try a new experiment. Create a study → Configure experiment → Use synthetic tooling fixtures. Set repetitions to 1, preview the matrix, freeze it and start a simulated run. New judge runs are clearly labeled simulation.
  4. Check portability. Click Download ZIP on your simulated run, then import it under Studies → Portable evidence. Importing inspects saved evidence and never starts inference.

Stop and reopen

Press Ctrl + C in the terminal to stop. Your workspace stays in the extracted folder. To reopen, run only the final command again—no reinstall needed.

# Linux / macOS
.venv/bin/python run.py

# Windows PowerShell
.\.venv\Scripts\python.exe run.py

Port 8000 already in use?

Choose another port and open the matching address. Leave other services running.

# Linux / macOS
.venv/bin/python run.py --port 8080

# Windows PowerShell
.\.venv\Scripts\python.exe run.py --port 8080

Then visit http://127.0.0.1:8080.

Common setup questions

Python is missing, or the version is different

Use Python 3.14 specifically; the wheel requires it. Install it from python.org, reopen your terminal and rerun the version command above. On Linux, you may also need your distribution’s matching Python 3.14 venv package.

The terminal cannot find run.py or requirements.lock

Extract the whole ZIP first, then open a terminal in the inner masklab-test-build directory. It contains run.py, requirements.lock, the wheel and README.txt. Running commands from Downloads or from inside the ZIP will not work.

Installation fails or the browser cannot connect

The first install needs internet access to the Python package index. Keep the hash checks enabled. If an install fails, save the error text and check that you are using Python 3.14. The browser address works only while run.py is running; check its terminal output for the port. These commands use the virtual environment directly, so PowerShell activation is unnecessary.

What is verified, and what data is saved?

Linux x86-64 setup is verified. Windows/macOS instructions are provided but have not been verified. Saved real responses are labeled live evidence; newly executed test-build runs are simulated. The launcher loads no credentials. Your local studies persist in the workspace directory beside run.py; restarting preserves them.

Prefer to build from source?

You will also need Git and Node 22. The README’s source setup instructions cover dependency installation, compiling the React interface and starting the Python app. The downloaded test build already includes the compiled interface.

What about fresh live inference?

The full source supports real NVIDIA Nemotron inference through Nebius Token Factory. Live owner use needs your own server-side credentials, reviewed model capabilities, an initialized spending ledger and explicit budget configuration. The judge launcher clears inherited provider settings and does not load .env. Do not publish keys or private databases.
